# 이 프로그램은 무엇인가 (비전공자용 설명)

프로그래밍을 몰라도 읽을 수 있게, 이 프로젝트가 **무엇을 하는 물건이고 안이 어떻게
생겼는지** 를 비유로 설명하는 문서입니다. 문법이나 코드는 다루지 않습니다.

---

## 1. 한 문장으로

> **가계부를 종이 대신 컴퓨터로 적는 프로그램**입니다.
> 마우스와 창은 없고, 검은 화면(터미널)에 **명령어를 타이핑해서** 씁니다.

앱 스토어의 가계부 앱과 하는 일은 같습니다. 다른 점은 버튼 대신 문장을 친다는 것뿐입니다.

| 앱에서 하던 일 | 여기서 치는 명령 |
| --- | --- |
| \+ 버튼 눌러 지출 입력 | `add` |
| 목록 화면 훑어보기 | `list` |
| 돋보기로 검색 | `search` |
| 이번 달 통계 보기 | `summary` |
| 한 건 지우기 / 고치기 | `delete` / `update` |
| 엑셀로 내보내기 / 가져오기 | `export` / `import` |

## 2. 실제로 쓰면 이런 모습입니다

한 달 예산을 정해두고,

```
$ python -m budget_app budget set --month 2024-05 --amount 200000
[저장 완료] 2024-05 예산 200000원
```

최근 내역을 보고,

```
$ python -m budget_app list --limit 3
TX-000004 | 2024-05-11 | expense | food | 28000 | 저녁 회식
TX-000003 | 2024-05-10 | income  | salary | 3000000 | 월급
TX-000002 | 2024-05-03 | expense | transport | 1400 | 지하철
```

이번 달을 결산합니다.

```
$ python -m budget_app summary --month 2024-05
총 수입: 3000000원
총 지출: 41400원
잔액: 2958600원
예산: 200000원 (사용률 20.7%)

지출 TOP 2
1) food 40000원
2) transport 1400원
```

`TX-000004` 는 영수증 번호 같은 것입니다. 나중에 그 한 건만 고치거나 지울 때 씁니다.

## 3. 적은 내용은 어디에 저장되나

데이터베이스 같은 거창한 것을 쓰지 않습니다. **그냥 메모장 파일**에 저장합니다.
`data` 라는 폴더 안에 파일 세 개가 생깁니다.

| 파일 | 안에 든 것 | 비유 |
| --- | --- | --- |
| `transactions.jsonl` | 실제 수입·지출 내역 | 가계부 본문 |
| `categories.jsonl` | 분류 이름 목록 (식비, 교통비…) | 가계부 앞장의 항목표 |
| `budgets.jsonl` | 달마다 정해둔 예산 | 표지 안쪽에 적어둔 이달 목표 |

내역 파일을 그대로 열어보면 이렇게 생겼습니다. **한 줄이 곧 한 건**입니다.

```
{"id": "TX-000001", "date": "2024-05-02", "type": "expense", "category": "food", "amount": 12000, "memo": "점심", "tags": ["회사"]}
{"id": "TX-000002", "date": "2024-05-03", "type": "expense", "category": "transport", "amount": 1400, "memo": "지하철", "tags": []}
```

한 줄에 한 건씩 적는 방식이라 **새 지출은 파일 맨 끝에 한 줄만 덧붙이면 끝**입니다.
장부의 마지막 줄 아래에 이어 쓰는 것과 똑같습니다. 앞의 내용은 건드리지 않습니다.

## 4. 프로그램 안은 어떻게 나뉘어 있나

코드는 한 덩어리가 아니라, **식당처럼 역할별로 나뉘어** 있습니다.
손님의 주문이 한 방향으로만 흘러가고, 거꾸로 가는 일은 없습니다.

```
   손님(사용자)
       │
       ▼
  ① 홀 직원  cli.py          주문을 받아 적고, 완성된 음식을 내어준다
       │
       ▼
  ② 주방장  services.py      "예산을 넘었나?" "이 분류가 있나?" 규칙을 판단한다
       │
       ▼
  ③ 창고 담당  repositories.py  재료(파일)를 꺼내오고 넣어둔다
       │
       ▼
  ④ 재료 규격  models.py       "지출 한 건은 날짜·금액·분류로 이뤄진다" 는 정의
```

여기에 조리 보조 셋이 붙습니다.

- **`validators.py` — 검수 담당.** "날짜가 `2024-13-45` 인데요?", "금액이 음수인데요?"
  를 걸러냅니다. 검수만 하고 손님에게 말을 걸지는 않습니다.
- **`errors.py` — 사과 문구 모음.** 문제 상황마다 **원인 한 줄 + 해결 힌트 한 줄**을
  미리 정해둡니다.
- **`decorators.py` — 홀 매니저.** 어디서 문제가 나든 손님 앞에서는 항상 같은 말투로
  사과하게 만듭니다.

**왜 이렇게 나눴나?** 나중에 저장 방식을 파일에서 진짜 데이터베이스로 바꾸고 싶으면
③번만 갈아끼우면 됩니다. ①②는 손도 안 댑니다. 반대로 화면 문구만 바꾸고 싶으면
①만 고칩니다.

## 5. 명령 하나를 쳤을 때 벌어지는 일

`add` 로 지출 한 건을 넣으면 순서대로 이렇게 흐릅니다.

```
1. 홀 직원   "날짜? 금액? 분류?" 하나씩 물어본다
2. 검수      "2024-5-2" 를 "2024-05-02" 로 다듬는다.
             "15,000" 의 쉼표를 떼서 15000 으로 만든다
             ↑ 틀린 값이면 그 자리에서 다시 물어본다. 프로그램이 죽지 않는다
3. 주방장    없는 분류면 거부한다. 새 영수증 번호를 뽑는다
4. 창고      파일 맨 끝에 한 줄 덧붙인다
5. 홀 직원   "[저장 완료] TX-000005" 를 화면에 찍는다
```

2번의 **다듬는 일**이 은근히 중요합니다. `2024-5-2` 와 `2024-05-02` 를 컴퓨터는 다른
글자로 봅니다. 들어올 때 모양을 통일해두지 않으면, 나중에 "5월 것만 모아줘" 했을 때
일부가 조용히 빠집니다.

## 6. 글자를 데이터로 바꾸는 일 — "파싱"

컴퓨터에 들어오는 것은 처음엔 전부 **그냥 글자**입니다. 우리가 친 명령어도, 파일에
적힌 내역도, 엑셀에서 뽑은 표도 컴퓨터 입장에서는 의미 없는 글자의 나열입니다.

> **파싱(parsing)** = 글자 덩어리를 **의미 있는 조각으로 쪼개고**, 계산할 수 있는
> **형태로 바꾸고**, 말이 되는 값인지 **확인하는** 일.

`"15,000"` 은 글자입니다. 글자끼리는 더할 수 없습니다. 합계를 내려면 반드시
숫자 `15000` 으로 바꿔야 합니다 — 이 변환이 파싱입니다.

이 프로그램에는 파싱하는 지점이 **네 군데** 있고, 각각 담당 파일이 정해져 있습니다.

| 어디서 | 무엇을 → 무엇으로 | 담당 |
| --- | --- | --- |
| 명령어 한 줄 | `list --limit 3` → 명령 이름 + 옵션값 | `cli.py` (argparse) |
| 사용자가 친 값 | `"15,000"` → 숫자 `15000` | `validators.py` |
| 저장 파일 한 줄 | `{"id": "TX-000001", …}` → 항목별 값 | `repositories.py` |
| CSV 한 행 | `2024-05-02,expense,food,…` → 칸별 값 | `services.py` |

아래 코드 조각은 실제 코드에서 가져온 것입니다. 읽기 편하도록 곁가지만 덜어냈습니다.

### 6-1. 명령어 한 줄 쪼개기

`list --limit 3` 을 쪼개는 코드를 직접 쓰지는 않습니다. **규칙만 등록**하고,
쪼개는 일은 파이썬에 기본으로 들어있는 `argparse` 라는 도구에게 맡깁니다.

```python
p_list = sub.add_parser("list", help="거래 목록 조회 (최신순)")
p_list.add_argument("--limit", type=int, default=20, metavar="N")
```

이 두 줄이 뜻하는 것:

| 적어둔 것 | 뜻 |
| --- | --- |
| `add_parser("list")` | `list` 라는 명령이 존재한다 |
| `--limit` | 그 명령은 `--limit` 라는 옵션을 받는다 |
| `type=int` | 받은 값은 **숫자로 바꿔서** 달라 (`"3"` → `3`) |
| `default=20` | 사용자가 안 쓰면 20으로 친다 |

그래서 `list --limit 3` 을 치면, 프로그램 안에서는 이런 상태가 됩니다.

```
args.command == "list"
args.limit   == 3        ← 글자 "3" 이 아니라 숫자 3
```

**왜 직접 쪼개지 않나?** 직접 하면 옵션 순서 바뀐 경우, 값이 빠진 경우, `--help`,
오타 났을 때 안내 문구까지 전부 손으로 만들어야 합니다. `argparse` 는 그걸 다
해주고, 잘못 쓰면 **사용법을 대신 출력**해 줍니다.

```
$ python -m budget_app import
usage: python -m budget_app import [-h] --from FILE.csv [--dry-run]
python -m budget_app import: error: the following arguments are required: --from
```

### 6-2. 값 다듬기 — 검사와 변환은 한 몸

여기가 이 프로젝트에서 가장 손이 많이 간 부분입니다. 금액을 다루는 함수 전체입니다.

```python
def parse_amount(value: str) -> int:
    """양수 정수만 허용한다. '15,000'처럼 천단위 쉼표가 있어도 받는다."""
    text = value.strip().replace(",", "")
    try:
        amount = int(text)
    except ValueError:
        raise ValidationError("금액은 숫자로 입력해야 합니다.", hint="예: 15000") from None
    if amount <= 0:
        raise ValidationError("금액은 0보다 큰 정수여야 합니다.", hint=f"입력값: {amount}")
    return amount
```

한 줄씩 읽으면:

| 코드 | 하는 일 |
| --- | --- |
| `value: str` → `-> int` | **글자를 받아 숫자를 돌려준다**는 약속 |
| `.strip()` | 앞뒤 공백을 떼어낸다 (`" 15000 "` → `"15000"`) |
| `.replace(",", "")` | 천단위 쉼표를 지운다 (`"15,000"` → `"15000"`) |
| `int(text)` | 글자를 숫자로 바꾼다 |
| `except ValueError:` | 못 바꾸면(`"만원"` 같은 경우) 파이썬 오류 대신 **우리말 안내**로 바꿔 던진다 |
| `if amount <= 0:` | 0원이나 음수 지출은 말이 안 되므로 거부한다 |

날짜는 더 짧습니다. **딱 한 줄에 검사와 다듬기가 같이** 들어 있습니다.

```python
return datetime.strptime(value.strip(), "%Y-%m-%d").strftime("%Y-%m-%d")
```

- `strptime` — 글자를 날짜로 **읽어들인다**. 이때 달력을 실제로 확인하기 때문에
  `2024-02-30`(2월 30일)이나 `2024-13-40` 이 여기서 걸립니다.
- `strftime` — 그 날짜를 **다시 정해진 모양으로 찍어낸다**. 그래서 `2024-1-5` 라고
  대충 쳐도 `2024-01-05` 로 통일되어 나옵니다.

**이 통일이 왜 중요한가?** "5월 것만 모아줘"를 처리할 때 프로그램은 날짜 글자의
앞 7자리(`2024-05`)를 비교합니다. `2024-5-2` 처럼 자릿수가 안 맞는 값이 하나라도
섞여 들어오면, 그 건은 **오류도 안 내고 조용히 5월 결산에서 빠집니다.** 들어올 때
모양을 맞춰두는 것이 나중에 조용한 누락을 막습니다.

### 6-3. 저장 파일 한 줄 → 내역 한 건

파일에서 읽어온 것도 처음엔 그냥 글자 한 줄입니다.

```
{"id": "TX-000001", "date": "2024-05-02", "type": "expense", "category": "food", "amount": 12000, ...}
```

이걸 두 단계로 바꿉니다.

```python
record = json.loads(line)                    # ① 글자 → 이름표 붙은 값 묶음
transaction = Transaction.from_dict(record)  # ② 값 묶음 → "내역 한 건"
```

**① `json.loads`** — 중괄호와 따옴표의 규칙을 해석해서 "id는 TX-000001, amount는
12000" 하는 식으로 이름표가 붙은 값 묶음을 만들어 줍니다. 이것도 파이썬에 기본으로
들어있는 도구라 직접 만들지 않습니다.

**② `from_dict`** — 그 값 묶음이 **내역의 규격에 맞는지 확인하고 규격품으로** 만듭니다.

```python
return cls(
    id=str(raw["id"]),
    date=str(raw["date"]),
    amount=int(raw["amount"]),
    ...
)
```

`int(raw["amount"])` 처럼 여기서도 한 번 더 형태를 못박습니다. 파일은 사람이
손으로 고칠 수도 있는 물건이라, 안에 뭐가 들었는지 믿을 수 없기 때문입니다.
필수 칸이 아예 빠져 있으면 `필수 필드가 없습니다: amount` 라고 알려줍니다.

> 통관 검사에 가깝습니다. 밖에서 들어온 물건은 일단 규격에 맞는지 확인하고,
> 통과한 것만 안쪽에서 씁니다. 그래서 프로그램 내부 코드는 "amount 는 무조건
> 숫자다"를 믿고 그냥 더하기만 하면 됩니다.

**그리고 한 줄이 깨져 있다면?**

```python
try:
    return json.loads(line)
except json.JSONDecodeError:
    warn(f"{path.name} {where}이 JSON 형식이 아닙니다 - 건너뜁니다")
    return None
```

**프로그램을 멈추지 않고 그 줄만 건너뜁니다.** 1,000건 중 한 줄이 깨졌다고 나머지
999건을 못 보게 되면, 사용자는 데이터를 되살릴 방법이 없습니다. 3장에서 말한
"한 줄에 한 건" 형식을 고른 실질적인 이유가 이것입니다 — 사고가 한 줄 안에 갇힙니다.

### 6-4. CSV 한 행 → 내역 한 건

엑셀에서 만든 표를 가져올 때입니다.

```python
reader = csv.DictReader(fp)
for lineno, row in enumerate(reader, start=2):   # 1행은 헤더라 2행부터
    transaction = Transaction(
        date=parse_date(row.get("date") or ""),
        type=parse_type(row.get("type") or ""),
        amount=parse_amount(row.get("amount") or ""),
        ...
    )
```

`DictReader` 는 **첫 줄(헤더)을 읽어서 각 칸에 이름을 붙여** 줍니다. 그래서 이후로는
`row["date"]` 처럼 칸 이름으로 꺼낼 수 있습니다. "따옴표 안의 쉼표는 칸 구분이
아니다" 같은 CSV 고유의 규칙도 이 도구가 알아서 처리합니다.

여기서 **가장 중요한 것은 `parse_date`, `parse_amount` 를 그대로 다시 쓴다**는 점입니다.
손으로 입력하든, 옵션으로 넣든, CSV로 밀어넣든 **통과 기준이 완전히 같습니다.**
검사 코드를 각자 따로 만들었다면, CSV로만 이상한 값이 들어오는 뒷문이 생겼을 겁니다.

한 행이 틀려도 전체를 취소하지 않습니다. 그 행만 건너뛰고 **몇 행이 왜 빠졌는지**
알려줍니다.

```
[완료] imported=4, skipped=0
```

---

### 정리

파싱은 결국 세 동작입니다.

```
쪼개기  →  형태 바꾸기  →  말이 되는지 확인
```

이 프로그램이 지킨 원칙은 하나입니다. **같은 종류의 파싱은 반드시 한 곳에서만 한다.**
금액을 해석하는 코드는 `parse_amount` 하나뿐이고, 대화형 입력·옵션 입력·CSV 가져오기가
전부 그 하나를 부릅니다. 규칙을 바꿀 일이 생기면 고칠 자리도 한 곳입니다.

## 7. 이 프로젝트가 특별히 신경 쓴 세 가지

### ① 내역이 10만 건이어도 목록은 즉시 뜬다

"최근 3건만 보여줘" 라고 했을 때, 보통은 파일을 처음부터 끝까지 다 읽고 마지막 3개를
고릅니다. 이 프로그램은 **파일의 뒤에서부터 거꾸로 읽습니다.** 3건을 채우는 순간 멈춥니다.

> 두꺼운 장부에서 어제 쓴 것을 찾을 때, 1페이지부터 넘기지 않고 뒤표지를 펴는 것과 같습니다.

10만 건(약 1MB)이 쌓인 상태에서 `list --limit 3` 은 파일의 **7% 정도만 읽고** 끝납니다.

### ② 저장 도중에 컴퓨터가 꺼져도 기존 기록이 날아가지 않는다

내역을 고치거나 지울 때는 원본 파일을 직접 덮어쓰지 않습니다.

```
1. 옆에 새 파일을 하나 만들어 전부 새로 쓴다
2. 다 썼는지 디스크에 확인받는다
3. 그제서야 파일 이름을 원본과 바꿔치기한다  ← 이 교체는 한순간에 일어난다
```

> 계약서를 수정할 때 원본에 줄 긋고 덧쓰는 대신, 새 종이에 다시 쓴 뒤 다 쓰고 나서
> 바꿔 끼우는 것과 같습니다. 쓰다가 손을 놓쳐도 원본은 그대로입니다.

1번이나 2번 도중에 전원이 나가면 **원본은 한 글자도 바뀌지 않은 채로 남습니다.**

### ③ 문제가 생겨도 사용자에게 암호문을 보여주지 않는다

없는 번호를 지우려고 하면, 프로그램이 죽으면서 알 수 없는 영문 오류를 쏟는 대신
이렇게만 말합니다.

```
$ python -m budget_app delete --id TX-000099
[오류] id=TX-000099 거래를 찾을 수 없습니다.
[힌트] list 명령으로 존재하는 id를 확인해 보세요.
```

**원인 한 줄 + 다음에 할 일 한 줄.** 프로그램 안에서 일어날 수 있는 사고 종류마다
이 두 줄을 미리 짝지어 두었습니다.

## 8. 파일 한 장 지도

| 파일 | 하는 일 | 한 줄 비유 |
| --- | --- | --- |
| `cli.py` | 명령어를 해석하고 결과를 화면에 찍는다 | 홀 직원 |
| `services.py` | 가계부의 규칙을 판단한다 | 주방장 |
| `repositories.py` | 파일을 읽고 쓴다 | 창고 담당 |
| `models.py` | "내역 한 건"의 생김새를 정의한다 | 재료 규격서 |
| `validators.py` | 입력값을 검사하고 모양을 다듬는다 | 검수 담당 |
| `errors.py` | 오류 문구와 힌트를 모아둔다 | 사과 문구 모음 |
| `decorators.py` | 모든 오류를 같은 말투로 바꿔 내보낸다 | 홀 매니저 |

## 9. 낯선 단어 사전

| 단어 | 쉬운 뜻 |
| --- | --- |
| **터미널 / CLI** | 그림 버튼 없이 글자만 치는 화면. 이 프로그램의 유일한 창구 |
| **JSONL** | 한 줄에 한 건씩 적는 메모장 형식. 사람이 열어봐도 읽힌다 |
| **CSV** | 엑셀이 열 수 있는 표 형식. 다른 프로그램과 주고받을 때만 쓴다 |
| **트랜잭션(transaction)** | 여기서는 **수입·지출 내역 한 건**. 은행 거래내역의 그 "거래" |
| **분류(category)** | 식비, 교통비 같은 항목 이름 |
| **예산(budget)** | 이번 달에 이만큼까지만 쓰겠다고 정해둔 금액 |
| **종료 코드** | 명령이 끝나면 조용히 남기는 성적표. `0`이면 성공, 그 외는 실패 |
